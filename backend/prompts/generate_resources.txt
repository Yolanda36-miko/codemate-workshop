## 资源生成规则

### 1. 输出数量与类型
严格按 resource_types 列表生成资源卡片，每个类型生成 1 个卡片。如果 resource_types 包含 3 种类型，就生成恰好 3 个卡片。

### 2. 标题要求
- 每个标题必须包含具体主题名称，格式为"{主题} — {资源类型}"
- 禁止使用泛泛的标题如"递归讲解"
- 示例正确标题："递归调用栈 — 图解讲解"、"二叉树遍历 — 代码示例"

### 3. 摘要要求
- summary 字段用 1-2 句话说明该资源的用途和特色
- 必须体现与基础水平和学习目标的关联

### 4. 按资源类型生成结构化 sections（Phase 3C 加厚标准：每种类型至少 7 个 sections）

**图解讲解** — 必须包含以下 section kinds（至少 7 个）：
- highlight: 核心要点提炼（1-2 句概括整个主题的精髓）
- example: 具体示例（用具体数据演示概念，如"以二叉树 [1,2,3,null,5] 为例"）
- steps: 分步骤拆解（至少 4 个步骤，用 steps 数组，每一步要包含具体的操作和数据变化）
- table: 对比表格（与相关概念的结构化对比，如递归 vs 迭代、BFS vs DFS，用三列以上表格）
- warnings: 常见误区（至少 2 个易混淆或易错的具体场景）
- practice: 即时练习（1 道配套练习题，让学习者验证是否真正理解了图解内容）
- answer_hint: 练习提示与参考答案（给出前一步练习的提示，但不是完整答案）

**代码示例** — 必须包含以下 section kinds（至少 7 个）：
- highlight: 代码整体说明（说明代码适用的数据范围和关键设计选择）
- code: 完整可运行代码（language 字段必须为 "{{ language }}"，不能是其他语言）
- steps: 代码阅读指南（至少 4 个步骤，用 steps 数组，每步对应代码中的一个关键段落）
- complexity: 时间/空间复杂度分析
- warnings: 注意事项（至少 2 个，如边界条件、特殊输入、性能陷阱）
- practice: 变式练习（给出 2 道变式题目，让学习者修改代码以适应新场景）
- next_action: 延伸学习建议（学完这个代码后，下一步建议学什么、为什么）

**易错点** — 必须包含以下 section kinds（至少 7 个）：
- highlight: 本主题最高频的错误类别概述
- warnings: 易错点详情（至少 3 个，每个包含：错误现象、根因分析、正确做法）
- compare: 错误 vs 正确对比（用双列表格或代码对比，直观展示差异）
- example: 具体犯错场景（用具体的输入数据演示错误如何被触发）
- text: 错误原因与修复方法（解释为什么写错、大脑如何被误导、如何避免再犯）
- practice: 判断纠错练习（给出 2 段可能有错误的代码，要求找出并修正）
- answer_hint: 纠错练习的提示与答案
特别规则：如果主题包含"快速排序"/"稳定性"/"不稳定排序"等关键词，必须包含一个编号为 [3a, 2, 3b, 1] 的反例演示，展示排序稳定性的破坏过程。

**分层练习** — 必须包含以下 section kinds（至少 7 个）：
- highlight: 练习整体说明（概述三个层次的递进关系和预期学习效果）
- practice: 基础层练习（至少 2 题，侧重概念理解和基本操作）
- answer_hint: 基础层提示（每题单独给出提示）
- practice: 进阶层练习（至少 2 题，侧重综合应用和多知识点联动）
- answer_hint: 进阶层提示
- practice: 提高层练习（至少 1 题，侧重优化和思维拓展）
- answer_hint: 提高层提示
- check_criteria: 每层达标标准（明确说明学完每层后应能做什么）
- warnings: 练习中的常见陷阱（指出做题时容易陷入的思维误区）
- next_action: 完成后建议（学完练习后下一步应进入哪个知识模块）

**项目案例** — 必须包含以下 section kinds（至少 7 个）：
- task: 项目任务描述（明确输入/输出/约束条件）
- steps: 分阶段实现步骤（至少 5 步，从设计→搭建→核心→优化→测试）
- design: 架构与数据结构设计（说明模块划分、核心数据结构选择、接口定义）
- code: 核心代码框架（language 必须为 "{{ language }}"，提供骨架代码和关键函数签名）
- warnings: 常见实现陷阱（至少 2 个，如并发问题、边界遗漏、性能瓶颈）
- next_action: 项目拓展方向（完成基础版本后的进阶挑战和延伸思考）

### 5. 内容厚度硬约束（Phase 3C-2：不满足以下任一条件则判定为不合格输出）

系统会对每张资源卡进行自动内容厚度验证。以下为各类型的硬性最低标准——不达标的内容将被判定为"thin content"并被自动补全逻辑替换。

**图解讲解** 硬性最低标准：
- highlight: ≥ 40 个中文字符（约 2 句话）
- example: ≥ 80 个中文字符，必须包含具体的数值或场景描述
- steps: ≥ 5 步，每步 ≥ 40 个中文字符（每步需包含具体操作和解释，不能是泛泛的"第X步：理解XX"）
- compare/text: ≥ 150 个中文字符的状态表/流程表/变化追踪表（需包含多行多列的表格结构）
- warning: ≥ 2 条，每条 ≥ 35 个中文字符（需包含具体的错误现象 + 原因）
- practice: ≥ 80 个中文字符（需是具体可执行的练习，不是泛泛的"请思考…"）
- answer_hint: ≥ 50 个中文字符（需给出具体的检查要点或解题方向）
- sections 总数: ≥ 7 个

**代码示例** 硬性最低标准：
- highlight: ≥ 40 个中文字符
- code: ≥ 20 行非空代码行，language 字段必须为 "{{ language }}"
- steps: ≥ 5 条逐段解释，每条 ≥ 45 个中文字符（每段需引用代码中的具体变量名/函数名/行号）
- complexity: 必须同时说明时间复杂度、空间复杂度及其推导依据（不能只给 O(N) 而不说为什么）
- warning: ≥ 3 条，每条 ≥ 35 个中文字符（覆盖边界/性能/语言特性三类陷阱）
- practice: ≥ 80 个中文字符的具体代码修改任务
- next_action: ≥ 60 个中文字符的延伸学习路径

**易错点** 硬性最低标准：
- warning: ≥ 4 个常见错误，每个 ≥ 40 个中文字符（包含错误现象 + 根因 + 纠正方法）
- compare: 必须包含"错误理解 / 正确理解 / 纠正方法"三列结构
- example: ≥ 100 个中文字符的具体反例场景
- text: ≥ 180 个中文字符的"为什么会错 / 错在哪里 / 如何避免"深度分析
- practice: ≥ 80 个中文字符的自测纠错题（需包含至少 2 段含错误代码供学习者排查）
- answer_hint: ≥ 60 个中文字符
- 特别规则：如果主题包含"快速排序""稳定性""不稳定""排序"任一关键词，必须包含 [3a, 2, 3b, 1] 反例演示，并说明 3a 和 3b 的相对顺序为何被破坏

**分层练习** 硬性最低标准：
- highlight: ≥ 40 个中文字符
- practice: 基础题、进阶题、综合题各至少 1 组，每组 ≥ 100 个中文字符（包含完整的题目描述，不能是"请做XX题"这种一句话题目）
- answer_hint: 必须分别给出三层的提示（共 ≥ 3 条 answer_hint）
- check_criteria: 必须分别给出三层的达标检查标准
- warning: ≥ 3 条做题误区（每条描述一个具体的错误学习行为及其后果）
- next_action: ≥ 80 个中文字符的练后学习路径

**项目案例** 硬性最低标准：
- task: ≥ 120 个中文字符（包含具体的项目背景、核心目标和详细要求）
- steps: ≥ 6 步，每步 ≥ 45 个中文字符（包含具体操作说明、检查点和常见坑点）
- text: ≥ 180 个中文字符的数据结构与架构设计说明
- code: ≥ 25 行核心代码骨架或伪代码
- warning: ≥ 3 个实现风险（每个描述具体的风险场景和防范措施）
- next_action: ≥ 3 个拓展方向，总字数 ≥ 100 个中文字符

**重要提醒**：
- 以上所有字数要求均为中文汉字的实际数量，不包含标点、空格和代码
- 如果 section kind 使用了 content 字段，内容必须写满；不能只写 1-2 句敷衍
- summary 字段保持简短（2-3 句话），详细内容必须写进 sections
- 如果 LLM 输出的 sections 内容长度不达标，系统会自动使用内容库进行补齐——为了避免自动补齐的内容与你的输出不一致，请务必在首次生成时就达到以上标准

### 6. 编程语言严格约束
- 所有 section 中的 language 字段必须为 "{{ language }}"
- 所有 codeBlock 或 code section 中的代码必须是 {{ language }} 语法
- 如果 {{ language }} 是 "C"，代码必须是标准 C 语法（printf, malloc），不能出现 C++ 语法
- 如果 {{ language }} 是 "C++"，可以使用 cout、vector、STL

### 7. 个性化匹配（Phase 3C: personalized_reason 必须提及所有可用画像字段）
- 如果基础水平为"基础薄弱"，内容应多包含基础概念解释和详细步骤
- 如果基础水平为"较好"，内容可更侧重进阶技巧和综合应用
- 如果学习目标为"考试复习"，侧重考点归纳和易错分析
- 如果学习目标为"刷题训练"，侧重代码示例和练习题
- 如果学习目标为"项目实践"，侧重项目案例和综合应用
- 如果当前困难点有具体内容，在对应资源中重点覆盖这些薄弱点
- personalized_reason 字段必须用自然中文段落，依次提及：基础水平 → 学习目标 → 编程语言 → 当前困难点 → 表达偏好，不能遗漏已有字段

### 8. 重点主题的深度内容（Phase 3C: 8 个优先主题的 rich content）
当知识主题匹配到以下 8 个高优先级主题时，必须在所有资源类型中提供远超通用标准的深度内容：

1. **二叉树前序遍历**（binary_tree_preorder）：
   - 必须包含前序/中序/后序的遍历顺序对比表
   - 用具体二叉树节点展示递归调用栈的压栈/弹栈过程
   - 警告：前序遍历 ≠ 层序遍历，很多初学者混淆二者
   - 图解讲解中应展示树结构图和访问路径标注

2. **快速排序为什么不稳定**（quicksort）：
   - 必须包含 [3a, 2, 3b, 1] 反例：对相等元素编号后演示 partition 如何打乱顺序
   - 对比归并排序的稳定性原理
   - 易错点类型必须将稳定性反例作为核心内容

3. **BFS和DFS**（bfs_dfs）：
   - 必须包含数据结构（队列 vs 栈）、空间复杂度、适用场景的三维度对比表
   - 用同一个图展示两种遍历产生的不同访问顺序
   - 警告：visited 标记的时机差异（入队时标记 vs 出队时标记）

4. **动态规划入门**（dp_intro）：
   - 必须展示"递归 → 记忆化搜索 → 自底向上 DP"的递进路径
   - 包含斐波那契和 0/1 背包的状态定义与转移方程
   - 练习层必须有至少 5 道覆盖三个难度的题目

5. **二分查找边界**（binary_search）：
   - 必须展示 `while left <= right` vs `while left < right` 两种模板的差异
   - 用具体数组演示 left/right/mid 的每一步变化
   - 警告：mid = (left + right) / 2 的整数溢出风险

6. **散列表与哈希冲突**（hash_table）：
   - 必须对比链地址法和开放寻址法的原理和优劣
   - 图示负载因子（load factor）从 0.25 到 0.9 时查询性能的变化
   - 示例：用两数之和问题演示哈希表的 O(n) 解法

7. **栈与队列应用**（stack_queue）：
   - 必须包含"用两个栈实现队列"和"用两个队列实现栈"的标准解法
   - 代码示例应包含括号匹配、逆波兰表达式两种完整实现
   - 分层练习覆盖：表达式求值、滑动窗口最大值、单调栈

8. **递归调用栈**（recursion_stack）：
   - 必须展示 factorial(3) 的压栈/弹栈帧变化表（每帧含参数值、返回地址、局部变量）
   - 对比树递归（二叉树）和线性递归（阶乘）的栈深度差异
   - 警告：递归过深导致栈溢出，Python 默认递归限制约 1000

### 9. 语言要求
所有文本内容使用简体中文，代码中的变量名可使用英文。

- estimated_time: 可选，如 "20 分钟"、"45 分钟"

- resource_cards 数组的长度必须等于 resource_types 的长度
- 所有代码的 language 字段必须是 "{{ language }}"
