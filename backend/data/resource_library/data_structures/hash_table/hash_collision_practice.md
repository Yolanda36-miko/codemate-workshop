## 每题提示

### 基础题一提示

使用取模运算 `key % 11` 计算每个 key 的哈希值，比较结果是否相同。

### 基础题二提示

### 进阶题一提示

### 进阶题二提示

线性探测法遇到冲突时，依次检查下一个位置（index+1, index+2, ...），直到找到空位。

### 进阶题三提示

### 综合题一提示

### 综合题二提示

键值对设计：key 为整数，value 为出现次数。注意负载因子和哈希函数的选择。

## 可选答案要点

### 基础题一答案

**哈希值计算**：

| key | 哈希值 (key % 11) |
|-----|-------------------|
| 15 | 15 % 11 = 4 |
| 27 | 27 % 11 = 5 |
| 38 | 38 % 11 = 5 |
| 49 | 49 % 11 = 5 |
| 50 | 50 % 11 = 6 |

**冲突分析**：

- 27、38、49 的哈希值都是 5，会发生冲突。

### 基础题二答案

**负载因子定义**：

负载因子 α = n / m，其中 n 是元素个数，m 是桶的大小。

**计算**：

α = 7 / 10 = 0.7

**应对措施**：

当负载因子超过 0.75 时，需要进行扩容（rehash），通常将桶的大小翻倍，并重新哈希所有元素。

### 进阶题一答案

**补全代码**：

```cpp
void insert(int key) {
    int index = hashFunction(key);
    HashNode* newNode = new HashNode(key);
    newNode->next = table[index];
    table[index] = newNode;
}
```

**头插法 vs 尾插法**：

| 方法 | 优点 | 缺点 |
|------|------|------|
| 头插法 | 插入速度快 O(1) | 逆序，改变插入顺序 |
| 尾插法 | 保持插入顺序 | 插入速度慢 O(n)，需要遍历到尾部 |

### 进阶题二答案

**插入过程**：

初始状态：`[_, _, _, _, _, _, _, _, _, _]`

| 步骤 | 插入 key | 哈希值 | 插入位置 | 是否冲突 | 数组状态 |
|------|----------|--------|----------|----------|----------|
| 1 | 12 | 12 % 10 = 2 | 2 | 否 | `[_, _, 12, _, _, _, _, _, _, _]` |
| 2 | 22 | 22 % 10 = 2 | 2→3 | **是** | `[_, _, 12, 22, _, _, _, _, _, _]` |
| 3 | 32 | 32 % 10 = 2 | 2→3→4 | **是** | `[_, _, 12, 22, 32, _, _, _, _, _]` |
| 4 | 42 | 42 % 10 = 2 | 2→3→4→5 | **是** | `[_, _, 12, 22, 32, 42, _, _, _, _]` |
| 5 | 5 | 5 % 10 = 5 | 5→6 | **是** | `[_, _, 12, 22, 32, 42, 5, _, _, _]` |

**冲突次数**：4 次（插入 22、32、42、5 时都发生了冲突）。

### 进阶题三答案

**平均查找长度趋势**：

| 负载因子 α | 链地址法平均查找长度 | 开放地址法（线性探测）平均查找长度 |
|-----------|---------------------|-----------------------------------|
| 0.5 | ~1.33 | ~1.5 |
| 0.75 | ~2 | ~2.5 |
| 0.9 | ~5 | ~5.5 |

**原因**：

当负载因子 α 接近 1 时，几乎每个位置都被占用，查找时需要遍历很长的链表或探测序列，导致性能急剧下降。

### 综合题一答案

**选择链地址法**：

**理由**：
- 实现简单，易于理解
- 不需要处理"墓碑"标记
- 适合频繁插入和删除的场景

**核心数据结构**：

```cpp
struct StudentNode {
    int id;
    string name;
    StudentNode* next;
    StudentNode(int i, string n) : id(i), name(n), next(nullptr) {}
};

class StudentHashTable {
private:
    vector<StudentNode*> table;
    int tableSize;
    
    int hash(int id) {
        return id % tableSize;
    }
};
```

**伪代码**：

```
function insert(id, name):
    index = hash(id)
    创建新节点
    如果桶为空，直接插入
    否则，遍历链表检查是否已存在
    如果存在，更新姓名；否则，插入链表

function search(id):
    index = hash(id)
    遍历链表查找 id
    找到返回姓名，未找到返回空

function remove(id):
    index = hash(id)
    遍历链表查找 id
    找到后删除节点，更新指针
```

### 综合题二答案

**键值对设计**：

- key：整数本身
- value：该整数出现的次数

**预计问题和优化**：

| 问题 | 优化方案 |
|------|---------|
| 冲突严重 | 使用均匀分布的哈希函数，定期 rehash |
| 内存占用大 | 使用链地址法，或选择合适的负载因子 |
| 插入速度慢 | 头插法，或使用更好的哈希函数 |

**数组替代方案**：

**可以使用数组**，因为整数范围已知（1~100000）。

**优点**：
- 查找速度 O(1)，无需哈希计算
- 实现简单

**缺点**：
- 空间浪费：如果大部分整数没有出现，数组中有很多空位
- 灵活性差：如果整数范围变化，需要重新分配数组

**对比**：

| 方法 | 空间效率 | 查找速度 | 灵活性 |
|------|---------|---------|--------|
| 哈希表 | 高（只存储存在的整数） | O(1) 平均 | 好（支持任意范围） |
| 数组 | 低（固定大小） | O(1) 确定 | 差（范围固定） |
