# 散列表与哈希冲突图解讲解

## 核心概念

### 散列表（Hash Table）

散列表是一种通过**哈希函数**将关键字（key）映射到数组位置（index）的数据结构，实现平均 O(1) 的查找、插入和删除操作。

### 哈希函数（Hash Function）

哈希函数将任意大小的输入映射为固定范围内的整数：

```
hash(key) → index (0 ≤ index < m)
```

其中 m 是数组大小。

### 哈希冲突（Hash Collision）

不同的 key 经过哈希函数计算后得到相同的 index，称为哈希冲突。根据鸽巢原理，当元素个数 n > 数组大小 m 时，冲突必然发生。

### 冲突解决方法

| 方法 | 原理 | 特点 |
|------|------|------|
| 链地址法（Separate Chaining） | 每个桶存储一个链表，冲突元素挂在链表上 | 实现简单，不易聚集 |
| 开放地址法（Open Addressing） | 冲突时寻找下一个空位置（线性探测、二次探测等） | 内存利用率高，可能产生聚集 |

### 负载因子（Load Factor）

负载因子 α = n / m，表示数组的填充程度：

- α 越小，冲突概率越低，但空间浪费越大
- α 越大，冲突概率越高，性能下降
- 通常当 α > 0.75 时需要扩容（rehash）

## 过程拆解

**场景设定**：
- 数组大小 m = 7
- 哈希函数：`hash(key) = key % 7`
- 插入顺序：10, 22, 31, 4, 15, 28
- 冲突处理：链地址法

### 步骤1：插入 10

```
hash(10) = 10 % 7 = 3
```

index 3 为空，直接存入。

### 步骤2：插入 22

```
hash(22) = 22 % 7 = 1
```

index 1 为空，直接存入。

### 步骤3：插入 31

```
hash(31) = 31 % 7 = 3
```

index 3 已被 10 占用，**冲突！** 使用链地址法，在 index 3 处创建链表，将 31 插入链表尾部。

### 步骤4：插入 4

```
hash(4) = 4 % 7 = 4
```

index 4 为空，直接存入。

### 步骤5：插入 15

```
hash(15) = 15 % 7 = 1
```

index 1 已被 22 占用，**冲突！** 在 index 1 处挂链表，插入 15。

### 步骤6：插入 28

```
hash(28) = 28 % 7 = 0
```

index 0 为空，直接存入。

## 状态变化表

| 步骤 | 插入的 key | 哈希值 | 是否冲突 | 数组状态（index 0-6） | 负载因子 α |
|------|-----------|--------|----------|----------------------|------------|
| 初始 | - | - | - | `[空, 空, 空, 空, 空, 空, 空]` | 0/7 = 0.00 |
| 1 | 10 | 3 | 否 | `[空, 空, 空, 10, 空, 空, 空]` | 1/7 ≈ 0.14 |
| 2 | 22 | 1 | 否 | `[空, 22, 空, 10, 空, 空, 空]` | 2/7 ≈ 0.29 |
| 3 | 31 | 3 | **是** | `[空, 22, 空, 10->31, 空, 空, 空]` | 3/7 ≈ 0.43 |
| 4 | 4 | 4 | 否 | `[空, 22, 空, 10->31, 4, 空, 空]` | 4/7 ≈ 0.57 |
| 5 | 15 | 1 | **是** | `[空, 22->15, 空, 10->31, 4, 空, 空]` | 5/7 ≈ 0.71 |
| 6 | 28 | 0 | 否 | `[28, 22->15, 空, 10->31, 4, 空, 空]` | 6/7 ≈ 0.86 |

### 状态变化详解

**步骤3 - 第一次冲突**：
```
数组状态：
index 0: 空
index 1: 22
index 2: 空
index 3: 10 → 31  (链表形成)
index 4: 空
index 5: 空
index 6: 空
```

**步骤5 - 第二次冲突**：
```
数组状态：
index 0: 空
index 1: 22 → 15  (链表形成)
index 2: 空
index 3: 10 → 31
index 4: 4
index 5: 空
index 6: 空
```

**步骤6 - 最终状态**：
```
数组状态：
index 0: 28
index 1: 22 → 15
index 2: 空
index 3: 10 → 31
index 4: 4
index 5: 空
index 6: 空
```

## 小规模具体例子

### 最终散列表结构

```
数组大小 m = 7

index 0: ──▶ 28
index 1: ──▶ 22 ──▶ 15
index 2: ──▶ 空
index 3: ──▶ 10 ──▶ 31
index 4: ──▶ 4
index 5: ──▶ 空
index 6: ──▶ 空

负载因子 α = 6/7 ≈ 0.86
```

### 查找过程演示

#### 查找 31

```
步骤1: hash(31) = 31 % 7 = 3
步骤2: 定位到 index 3
步骤3: 遍历链表 [10, 31]
步骤4: 找到 31，返回对应值
```

**比较次数**：2 次（先比较 10，再比较 31）

#### 查找 28

```
步骤1: hash(28) = 28 % 7 = 0
步骤2: 定位到 index 0
步骤3: 直接找到 28，返回对应值
```

**比较次数**：1 次

### 时间复杂度分析

| 情况 | 查找复杂度 | 原因 |
|------|-----------|------|
| 理想情况 | O(1) | 哈希函数均匀分布，每个桶只有一个元素 |
| 平均情况 | O(1) | 负载因子控制在合理范围，链表长度较短 |
| 最坏情况 | O(n) | 所有元素映射到同一个桶，退化为链表查找 |

## 易错提醒

### 错误理解哈希函数

**错误**：以为哈希函数是加密函数，需要隐藏原始数据。

**正确**：哈希函数是确定性映射，同一输入必须产生同一输出，不需要保密。

### 忽略冲突处理

**错误**：以为不同的 key 一定能映射到不同的位置。

**正确**：根据鸽巢原理，冲突不可避免，必须设计冲突处理机制。

### 负载因子过高不处理

**错误**：持续插入元素，负载因子超过 0.75 后性能急剧下降。

**正确**：当负载因子超过阈值时，需要扩容数组并重新哈希（rehash）。

### 链表法 vs 开放地址法选择误区

| 误区 | 正确理解 |
|------|---------|
| 链表法浪费空间 | 链表法需要额外指针，但实现简单、不易聚集 |
| 开放地址法一定更好 | 开放地址法内存利用率高，但易产生"聚集"问题 |

### 哈希函数设计不当

**错误**：使用对输入不敏感的哈希函数，例如对字符串只取第一个字符。

**正确**：哈希函数应尽量均匀分布，对输入的微小变化产生显著不同的输出。

## 小练习

### 练习题目

**场景**：数组大小 m = 7，哈希函数 `hash(key) = key % 7`，依次插入：12, 26, 19, 33, 5。

**要求**：
1. 用链地址法模拟插入过程，画出最终数组和链表结构。
2. 计算最终的负载因子。
3. 如果改用线性探测法（开放地址法），数组状态会变成什么样？

### 答案要点

#### 1. 链地址法

**计算哈希值**：
- hash(12) = 12 % 7 = 5
- hash(26) = 26 % 7 = 5（冲突）
- hash(19) = 19 % 7 = 5（冲突）
- hash(33) = 33 % 7 = 5（冲突）
- hash(5) = 5 % 7 = 5（冲突）

**最终状态**：
```
index 0: 空
index 1: 空
index 2: 空
index 3: 空
index 4: 空
index 5: 12 → 26 → 19 → 33 → 5
index 6: 空
```

**负载因子**：α = 5/7 ≈ 0.71

#### 2. 线性探测法

**插入过程**：
- 12 → index 5（空，存入）
- 26 → index 5（冲突）→ index 6（空，存入）
- 19 → index 5（冲突）→ index 6（冲突）→ index 0（空，存入）
- 33 → index 5（冲突）→ index 6（冲突）→ index 0（冲突）→ index 1（空，存入）
- 5 → index 5（冲突）→ index 6（冲突）→ index 0（冲突）→ index 1（冲突）→ index 2（空，存入）

**最终状态**：
```
index 0: 19
index 1: 33
index 2: 5
index 3: 空
index 4: 空
index 5: 12
index 6: 26
```

### 验证方法

1. **哈希值计算**：手动计算每个 key 的 hash 值，验证是否正确。
2. **链表结构**：检查链表顺序是否与插入顺序一致（链地址法通常插入链表尾部）。
3. **线性探测**：检查每次冲突后是否正确找到下一个空位置。
4. **负载因子**：确认元素个数 n = 5，数组大小 m = 7，α = 5/7。
